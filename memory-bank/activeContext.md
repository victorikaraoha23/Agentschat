## Current focus

Standing up the skeleton that everything else hangs off — the backend package (`src/main.py`,
`src/config.py`, `src/db.py`, `src/api/`, `src/models/`), the Alembic environment, and the Next.js
app shell — so that `pytest`, `mypy --strict src`, `tsc --noEmit`, `eslint`, and `vitest` all have
something real to run against.

## Immediate next steps (proposed — not yet approved)

1. **Backend scaffold.** `pyproject.toml` (Python 3.11, FastAPI, SQLAlchemy 2.0 async, Alembic,
   LiteLLM, pydantic-settings, pytest, mypy, ruff), then `src/config.py`, `src/db.py`, and
   `src/main.py` with lifespan + a health route.
2. **First migration.** `users`, `workspaces`, `workspace_balances` — autogenerated then
   hand-reviewed, with `ALTER TABLE ... ENABLE ROW LEVEL SECURITY` on every table, verified via
   `upgrade head` → `downgrade -1` → `upgrade head`.
3. **Test harness.** `tests/conftest.py` with `db`, `db_commit`, `client`, `client_commit`,
   `mock_llm`, `mock_redis`, plus `tests/factories.py` and `tests/concurrency.py`.
4. **Credit service.** `src/services/credit_service.py` implementing the ledger contract *before*
   anything in the product spends a credit.
5. **Frontend scaffold.** Next.js App Router + TypeScript strict + ESLint + vitest + MSW, then
   `lib/api.ts`, `lib/sse.ts`, and `lib/idempotency.ts`.

Ordering rationale: (1)–(3) unblock every later test, and (4) must exist before chat or jobs can
charge anything.
